# spinel-ebpf OTLP export (ADR-012 / P003)

Material for sending the telemetry spinel-ebpf collects to an OpenTelemetry Collector over
**OTLP/HTTP+protobuf**. The encoder is nanopb (`src/runtime/otlp/`), and transport is a POSIX socket
HTTP/1.1 client (`src/runtime/otlp/otlp_http.{c,h}`).

- Schema source of truth: `third_party/opentelemetry-proto` (v1.10.0)
- C encoder: `src/runtime/otlp/pb/**` (generated by nanopb, regenerated with `scripts/regen-otlp-pb.sh`)
- Design: ADR-012 /
  roadmap: P003

## S1: checking that transport works

### (a) No real Collector needed — verify with a mock receiver (default)

```sh
sh tests/runtime/run_otlp_send.sh
```

`tests/runtime/mock_otlp_receiver.rb` (CRuby) receives `POST /v1/metrics`, restores the body with
`protoc --decode` and asserts on it (complete on the host alone).

### (b) Send to a real Collector

1. Start the Collector (docker example):
   ```sh
   docker run --rm -p 4318:4318 -p 4317:4317 \
     -v "$PWD/examples/observability/otlp/collector-config.yaml:/etc/otelcol/config.yaml" \
     otel/opentelemetry-collector-contrib:latest --config /etc/otelcol/config.yaml
   ```
2. Point the send test at the real Collector (`:4318`):
   ```sh
   OTLP_PORT=4318 OTLP_NO_MOCK=1 sh tests/runtime/run_otlp_send.sh
   ```
3. It is OK when `spnl_method_calls_total` and the like appear in the Collector's debug exporter log.

## Current state (as of S1)

- What is sent is a **sample** ExportMetricsServiceRequest (fixed values). Carrying the real metrics of `--instrument`
  in this OTLP is done in **S2** (P003).
- The transport is HTTP+protobuf only. gRPC (`:4317`) comes later (S5). TLS is not supported.
