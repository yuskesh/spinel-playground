# examples/image — image processing written in Ruby, on the Apple GPU

Two pipelines over 4K images, written with the tensor surface
([tools/tensor](../../tools/tensor/README.md)) and run on the CPU (`local-sync`)
or the Apple GPU (`metal`). The prerequisites are those of
[examples/tensor](../tensor/README.md), and `env.sh` also reads
`examples/tensor/iree.env`.

The test images are generated by `mkimages.rb` into `img/` (gitignored): a 4K
photograph-like image and three synthetic ones (`uhd`, `uhd_r005`, `uhd_ramp`,
`uhd_flat`). Each is 8.3 MB, and they are not remade when present.

## filter

A three-stage pipeline in three `tensor_def`s: `blur_f32`, `sobel_f32`, and
then either `thresh_u8` or `gain_u8`. The two f32 intermediates stay on the
device, and only the final u8 image is read back:

- 3 invocations, 1 upload (the image), **0 downloads before the readback**
  (the intermediates never cross to the host), and one readback of exactly one
  image's bytes;
- the output is identical on CPU and Metal, for both tails.

The blur and Sobel windows border the image with a padding whose lowering
depends on the device, so the importer writes one module per device profile.

## resize

A separable resample in two `tensor_def`s (`tap_y_f32`, then `tap_x_u8`), with
the taps built on the host and passed as tensors:

- 2 invocations, 5 uploads (the image and four coefficient tensors), **0
  downloads before the readback**, and one readback of the output's bytes;
- the output is identical on CPU and Metal, for all three reductions (4K to
  1080p, which is dyadic; to 1620x911, which is not; and to 720p);
- **an output size that is not a multiple of 4 is refused**, because
  metal-spirv would silently write a u8 destination short.

## Checked

`tests/tensor/run.sh` builds both and checks exactly the claims above on both
devices, including the refusal.

The reason these examples exist in spinel-llvm, **pixel-exact agreement with a
reference implementation** (`ref.c`, a second f32 implementation of each
filter), is an oracle. It runs only with `SPINEL_ORACLE=1`, which the test never
sets. Without it, the programs print what the device run itself established.
